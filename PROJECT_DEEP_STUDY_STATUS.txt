1. EXECUTIVE SUMMARY & WHAT THIS PROJECT IS
================================================================================

The KDL Starter Kit (also known as KDL OS / Kalam Dream Labs OS) is a modular,
production-grade enterprise web platform, CMS, visual page builder, design-system
compiler, and website generation engine. 

The project has two distinct primary purposes:
1. AN AUTONOMOUS, AI-AGENT-BUILDABLE SAAS FOUNDATION:
   Architected from day one so that autonomous AI agents (Orchestrator, Backend
   Architect, Backend Coder, Frontend Architect, Frontend Coder, DevOps, AI Services,
   Code Reviewer, Documentation) develop, test, and document the platform using
   a two-brain system (Claude for architecture/review, OpenRouter for code/docs)
   with strict handoff protocols and review gates.

2. A MODERN BUSINESS SITE BUILDER & PUBLISHER:
   A visual, data-bound web publishing system (demonstrated end-to-end using the
   Subhadra Group commercial construction & infrastructure reference implementation).
   Unlike traditional template-based sites where text is hardcoded or trapped inside
   opaque JSON blobs, KDL OS separates structured content into real database models
   (Team, FAQ, Sectors, Catalog, Case Studies, Menus, Settings Fields) which are
   reactively bound to visual components (Puck Builder and Section Builder) and
   published as an ultra-fast, single-origin Next.js site.

Key Stats:
- 28 Backend Modules (26 fully implemented, 2 UI stubs)
- 9 Docker Services (all running and healthy on local stack)
- Over 1,290 Passing Backend Tests & 279 Passing Frontend Tests
- 13/13 Passing AI Services Suites (94 tests)
- 40+ Pre-built, multi-variant Construction & General design blocks
- 11 Dynamic Sector detail pages, 8 Catalog items, 5 Work items, 2 Founders, 6 FAQs

4. DEEP INVENTORY: WHAT IS WORKING (FUNCTION-BY-FUNCTION)
================================================================================

--------------------------------------------------------------------------------
4.1 CORE FOUNDATION & AUTHENTICATION (Module: auth, users)
--------------------------------------------------------------------------------
- User registration and login with email + password.
- Password hashing using bcrypt with minimum 12-character security rules.
- Dual JWT auth tokens: Access Token (short-lived) + Refresh Token (httpOnly cookie).
- Progressive account lockout in Redis upon repeated failed attempts (1m, 5m, 30m).
- Forced password change workflow on first login (`must_change_password: true`).
- Password reset self-service flow via signed email token.
- Token revocation and user suspension (`status: SUSPENDED`) returning instant 403.
- Soft-delete support for users (`deleted_at`).
- Admin credential recovery CLI (`scripts/reset-admin-password.js`).

--------------------------------------------------------------------------------
4.2 USER MANAGEMENT & RBAC (Module: user-management)
--------------------------------------------------------------------------------
- Role-Based Access Control (RBAC) supporting custom roles and granular permissions.
- `requirePermission(moduleName, action)` middleware protecting all mutation routes.
- Super Admin (`slug: 'super-admin'`) automatic authorization bypass.
- User-specific permission overrides (grant or deny specific module permissions).
- Permission matrix endpoint (`GET /api/permissions/matrix`) for admin UI.
- Fast permission resolution cached in Redis (`perm:user:{id}`) with auto-invalidation
  on role or override mutations.
- PII-scrubbed activity audit logging (`writeActivity` / `shared/activity-logger.js`).

--------------------------------------------------------------------------------
4.3 TEMPLATE ENGINE (9-STAGE DAG ORCHESTRATOR) (Module: template-engine)
--------------------------------------------------------------------------------
- 9-Stage directed acyclic graph (DAG) state machine:
  1. Intake: Logo intake + company contact form (email, phone, address).
  2. Palette: OKLCH extraction, dominant color analysis, WCAG AA contrast check.
  3. Inference: AI brand personality, tone, taglines, and marketing copy.
  4. Approval: Brand confirmation, palette lock, and approval tokens.
  5. Guidelines: Typography token compilation (Poppins, Sora, Inter) across devices.
  6. Collateral: Print-ready visiting cards, letterheads, t-shirts, ID cards.
  7. Website: Multi-page selection, Header/Footer layout picker, live Puck editor.
  8. Preflight: Comprehensive validation rules verifying brand, site chrome, and pages.
  9. Export: Static site generator producing a clean Next.js export bundle.
- Server-side stage gate verification returning 409 `STAGE_GATE_FAILED` if prerequisites
  are not satisfied.
- Automated crash recovery and interrupted stage detection.
- Multi-tenancy project isolation via `X-Project-Id` validation middleware.

--------------------------------------------------------------------------------
4.4 PAGE BUILDER & PUCK COMPONENT PACKS (Module: page-builder)
--------------------------------------------------------------------------------
- Integrated Puck Visual Editor at `/admin/template-engine/edit/[id]`.
- Draft vs Published page status lifecycle.
- Over 40 production-grade visual blocks under `packs/construction` and `packs/general`:
  - Hero: 4 design variants (Carousels, Video backgrounds, Brand logo tracks).
  - Inner Banner: 4 designs with dynamic breadcrumb support.
  - Sectors Grid & Detail List: 4 designs with jump pills and scroll reveal.
  - Disciplines & Capabilities: Interactive icon cards and technical grids.
  - Our Brands: Multi-tab category filters rendering 99+ real vendor logos.
  - Featured Projects & Case Studies: Carousels and split showcase presentations.
  - Testimonials: Slider with video modal support.
  - Team / Founder Profile: Founder bio cards with real data binding.
  - FAQ & Lead Capture: Collapsible accordions with inquiry form.
  - Contact & Office Info: Interactive maps, showroom details, branch data.
  - Footer & Top Bar: Dynamic nav links, contact cards, social icons.
- Array-based repeating items (via `numbered-families.json`) allowing arbitrary
  Add / Remove / Reorder of slides, FAQs, features, and brand logos without flat props.
- Solid-on-scroll header behavior based on whether the underlying block is a hero.
- Clean Style Tab vs Content Tab separation in the Puck inspector panel.

--------------------------------------------------------------------------------
4.5 SECTION BUILDER (VISUAL ATOM COMPOSER ENGINE) (Module: custom-blocks)
--------------------------------------------------------------------------------
- Canvas-based custom section builder at `/admin/page-builder/section-builder`.
- Atom elements library: Container, Row, Column, Heading, Text, Button, Logo,
  Live Menu Nav, Image.
- 12-Column responsive grid system with interactive drag-resize handles.
- Per-element width specification (1 to 12 columns).
- Saved Section Builder blocks can be saved as project-scoped reusable components.
- Seamless Layout Step integration: Custom saved headers, top-headers, and footers
  can be selected in the Template Engine Layout step (`custom:<id>`) and applied
  globally across every page in the project.

--------------------------------------------------------------------------------
4.6 HIERARCHICAL MENUS & NAVIGATION (Module: menus)
--------------------------------------------------------------------------------
- 3-Level hierarchical navigation support (Main Item -> Sub Menu -> Flyout Item).
- Adjacency list Prisma database model (`parent_id`) with application-enforced
  depth limits (maximum depth: 3).
- WordPress-style two-pane Admin UI at `/admin/menus`.
- Native HTML5 Drag-and-Drop: Drag onto an item to nest; drag to top/bottom edge to
  reorder as siblings.
- Batch reordering endpoint saving full tree state in a single transaction.
- Stored-XSS security allowlist preventing `javascript:` or `data:` URL injections.
- Public unauthenticated tree endpoint (`GET /api/menus/public?key=header&project_id=`).
- Pure CSS hover flyout dropdowns implemented via Tailwind named groups (`group/l1`).

--------------------------------------------------------------------------------
5.1 FAILING UNIT & REGRESSION TESTS (4 TEST SUITES AFFECTED)
--------------------------------------------------------------------------------
Although the runtime application works cleanly in Docker, automated tests have
drifted following recent feature additions:

1. Backend: `backend/src/modules/catalog/seed-content.test.js`
   - Symptom: Fails immediately with `Error: DATABASE_URL environment variable is not set`.
   - Root Cause: `src/config/database.js` initializes Prisma at module import time.
     The unit test executes without setting a mock `DATABASE_URL` in its environment.
   - Fix Needed: Add mock environment setup or mock `@prisma/client` before imports.

2. Backend: `backend/src/modules/template-engine/drivers/website.driver.test.js` (19 test failures)
   - Symptom: `TypeError: Cannot read properties of undefined (reading 'id')` at line 463.
   - Root Cause: Recent commit `633ebb2` added automatic publishing on page creation:
     `page = await updatePage(page.id, { status: 'PUBLISHED' }, userId);`
     `pageKeyToId[key] = page.id;`
     The test suite's mock for `updatePage` does not return the updated page object
     (it returns `undefined`), causing `page.id` to throw when accessing the returned object.
   - Fix Needed: Update `updatePage.mockResolvedValue({ id: 'mock-page-id', ... })` in the test.

3. Frontend: `frontend/tests/rtl/regression/template-engine-website-stage.test.tsx`
   - Symptom: Test assertion fails looking for text `"2 pages assembled"`.
   - Root Cause: The website stage UI was updated to show sector pages:
     Header now renders e.g. `"7 pages + 11 sector detail pages assembled"`.
   - Fix Needed: Update the RTL test expectation to match the new dynamic count format.

4. Frontend: `frontend/tests/regression/block-variants-gallery.test.ts` (3 test failures)
   - Symptom: `AssertionError: ... has a multi-design variant field but no blockVariants entry`.
   - Root Cause: Three components (`ConstructionIconFeatureGrid`, `ConstructionApproachSplit`,
     `ConstructionProcessSteps`) added a `variant` prop for multi-design switching,
     but were not added to the `blockVariants` test gallery registration table.
   - Fix Needed: Register the variant options in `block-variants-gallery.test.ts`.

--------------------------------------------------------------------------------
5.2 PARTIAL & INCOMPLETE FEATURE IMPLEMENTATIONS
--------------------------------------------------------------------------------
1. Navigation Menu Tree Rendering Scope (Menus Module):
   - Only `ConstructionHeader` Design 1 desktop navigation currently consumes the
     live 3-level Menu tree from the `menus` module.
   - Designs 2, 3, 4, the mobile hamburger drawer, and standard `NavBar` still fall
     back to flat static `links`. Mobile users cannot currently view sub-menus.

2. SEO & Metadata on Dynamic Sector Pages:
   - Dynamic `/sectors/[slug]` pages currently use client-side `<title>` and `<meta>` tags.
   - Full SSR-crawlable metadata (Next.js `generateMetadata` Server Component) is not
     yet implemented, which limits search engine indexing for dynamic sectors.

3. Placeholder Stock Photography:
   - While 90% of assets were ported from the reference site (152+ assets in `/seed/`),
     three sectors (Government, Premium Flats, Gated Communities) still use Unsplash
     placeholder photography because no local assets existed in the client bundle.

4. Stubbed Backend Modules:
   - `page-builder-ui`: Nav-only stub router without controller/service (intentional shim).
   - `theme-engine-ui`: Nav-only stub router without controller/service.
   - `storage-settings`: Settings submodule missing standard `module.json` manifest.

--------------------------------------------------------------------------------
5.3 EDITOR & PAGE-BUILDER KNOWN LIMITATIONS
--------------------------------------------------------------------------------
1. No Automatic Saving (Autosave):
   - The visual page builder does NOT autosave edits while typing or dragging.
   - Edits are only persisted to PostgreSQL when the user explicitly clicks the "Save"
     (formerly "Publish") button. A browser refresh mid-edit will lose changes.

2. Canvas Click Inaccessibility for Page Chrome:
   - Header and Footer are treated as layout chrome wrapping the page content.
   - They cannot be clicked or edited directly inside the Puck visual canvas. They must
     be configured via the Layout step, Section Builder, or the Menus admin.

3. Component Prop Renaming Breaking Legacy Instances:
   - Transitioning from flat numbered props (e.g. `faq1Question`) to array props
     (`type: 'array'`) requires running the migration script or re-inserting blocks.
     Legacy pages that have not undergone normalizer passes may render empty accordions.

--------------------------------------------------------------------------------
5.4 MULTI-TENANCY GAPS
--------------------------------------------------------------------------------
1. Global Setting-Fields Lack Project Scoping:
   - The `setting-fields` module stores values in a global table (`SettingValue`)
     without a `project_id` foreign key.
   - As a result, global text items (Vision, Mission, Taglines) are shared across all
     projects on the instance. Two distinct client projects cannot have differing
     Vision/Mission text in the current schema without extending `setting-fields`.

--------------------------------------------------------------------------------
5.5 DEPENDENCY, LOCKFILE & CI OUTAGES
--------------------------------------------------------------------------------
1. Dependabot PR Backlog:
   - 14 open Dependabot PRs (#285 to #304) touching `@anthropic-ai/sdk`, `next`, `vitest`,
     `sharp`, `multer`, etc.
   - Several frontend/backend lockfiles have conflicting dependencies that caused CI to fail.
2. Direct-to-Master Commit Discipline:
   - Rule KDL-520 strictly prohibits direct pushes to master. Past bypasses caused
     PRs to close with `mergedAt=null`, requiring manual ledger reconciliation.
