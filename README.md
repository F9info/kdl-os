# KDL Starter Kit

**Generic production-ready SaaS boilerplate by [Kalam Dream Labs Pvt Ltd](https://kalamdreamlabs.com)**

---

## Overview

KDL Starter Kit is a fully AI-agent-buildable SaaS foundation. Every service is containerised, every module is isolated, and every line of production code is generated by AI agents following a structured phase plan. Humans approve phases — not individual PRs.

The finished product is **KDL OS**: a modular, no-code project builder. One installation can run an **Admin** app, a **Website** (CMS, menus, visual Section Builder, themes, SEO, preview and publish), **Landing Pages**, forms and media, in any combination, and a Website can also be exported as a **static site**. Modules are installed and enabled from the admin (Settings > Products and Modules); no source edits are needed to build a project.

## Quick Start

New to this? Follow the step-by-step guide: [docs/INSTALLATION_GUIDE_SIMPLE.md](docs/INSTALLATION_GUIDE_SIMPLE.md) (full version: [docs/INSTALLATION_GUIDE.md](docs/INSTALLATION_GUIDE.md)).

### Start a new client project

```bash
# 1. Clone the kit into a folder named after the client project
git clone https://github.com/F9info/kdl-os.git acme-crm
cd acme-crm

# 2. Create a NEW .env for this project (do not copy one from another project)
./setup.sh --env-only
#   - Docker project name = the folder name (acme-crm); refused if another folder uses it
#   - database name = the folder name with _ (acme_crm); choose another with --db <name>
#   - its own free port block, e.g. block 1 = ports 10100–10112
#   - new random passwords and secrets
#   - docker-compose.override.yml: local memory caps
#   It prints this project's addresses. Options: --name <name>, --db <name>, --block <N>.

# 3. Optional: add extra keys you need (e.g. OPENROUTER_API_KEY / ANTHROPIC_API_KEY for AI)
#    by copying ONLY those lines into .env.

# 4. Build and start. The backend creates the database tables by itself on start.
docker compose up -d --build
docker compose ps            # wait until `backend` is healthy (first build: 10–20 minutes)
```

Then open the **installation wizard** in the browser:

```
http://localhost:<KDL_PORT_FRONTEND>/install      block 1: http://localhost:10101/install
```

(`setup.sh` prints the exact address; `KDL_PORT_FRONTEND` is in the project's `.env`.) On a new, empty
database it walks you through company details, the database check, the first admin account, and which
products to turn on. Sign-in stays closed until the wizard is finished. Afterwards the admin app is at
`http://localhost:<KDL_PORT_FRONTEND>` and the public website at `http://localhost:<KDL_PORT_HTTP>`.

> **Never copy a `.env` from another project.** It carries that project's Docker name
> (`COMPOSE_PROJECT_NAME`) and ports (`KDL_PORT_*`): the new folder would take over the other project's
> containers and database, or fail with "port is already allocated". A `.env` without a project name
> (e.g. kdl-os's own) makes the new folder share kdl-os's database. Copy only individual keys you need,
> never `COMPOSE_PROJECT_NAME`, `KDL_PORT_*` or passwords/secrets.
>
> Several projects on one machine (names, port blocks, memory, Docker Desktop 12 GB):
> [docs/MULTI_PROJECT_LOCAL.md](docs/MULTI_PROJECT_LOCAL.md).

`./setup.sh` without `--env-only` does steps 2 and 4 in one go and also loads the starter data.

Forgot the admin password (or locked out after too many failed sign-ins): reset it with

```bash
docker compose exec backend node scripts/reset-admin-password.js appra
```

Then sign in as `admin@kdl.com` with `Admin@123`. Outside production the password must be at least 8 characters; with `NODE_ENV=production` it must be at least 12 and `--force` is required. This is a development password: change it before any shared or production use.

## Service URLs

Classic ports (port block 0). A project on block N uses `10000 + N×100` upwards instead — its own
ports are the `KDL_PORT_*` lines in its `.env` (table in [docs/MULTI_PROJECT_LOCAL.md](docs/MULTI_PROJECT_LOCAL.md)).

| Service | URL | Notes |
|---------|-----|-------|
| Frontend | http://localhost:3001 | Next.js admin panel and public site |
| Backend API | http://localhost:4000 | Express REST API |
| AI Services | http://localhost:5001 | LLM orchestration layer |
| Nginx (proxy, use this one) | http://localhost | Routes `/api` → backend, `/ai` → ai-services, `/` → frontend |
| MinIO API | http://localhost:9002 | S3-compatible object storage |
| MinIO Console | http://localhost:9003 | MinIO admin UI |
| MeiliSearch | http://localhost:7700 | Full-text search dashboard |
| ChromaDB | http://localhost:8000 | Vector store |

## Production Run

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

Production overrides: `restart: always`, `NODE_ENV: production`, no host ports exposed except Nginx :80.
