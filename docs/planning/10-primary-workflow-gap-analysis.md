| 2 | Two roles, Developer and Admin, each with own dashboard + RBAC | **Resolved 2026-11-06** | New `developer` system role. One policy file (`backend/src/modules/user-management/shared/role-blueprints.js`) defines Developer (every module except `roles:delete` / `permissions:delete`) and Admin (users, media, settings and all website content modules in full; view-only on themes, templates, projects; no modules, integrations or credits; unknown modules default to Developer-only). Applied at fresh install (seed), once at backend start on existing databases (marker `rbac.blueprint_version`, so later revocations stick), and for each newly installed module. Before this, **Admin had no permission on any website module** (only super-admin could build a site). Dashboards are permission-driven: stat cards plus Build / Content quick actions per what the role can open. Verified live with probe users: Developer `/modules` 200, Admin 403; Admin dashboard = Content only. Create a Developer from Users > role "Developer". |

Static Website used to be only an export card; the Website product now has a **delivery** choice (web application / static website / both) in Settings > Products and the Setup Wizard (stored as `products.website_delivery`, API `PUT /api/modules/products {products, delivery}`, returned by `GET /api/modules/graph`). |
| 6 | Combinations 1–7 in one install | **Resolved 2026-11-06** | All seven are explicit and named: Admin project; Web application; Static website; Landing pages; Web application + Landing pages; Static website + Landing pages; Web application + Static website + Landing pages. The picker shows "Your project: ..." (`admin/lib/project-type.ts`, one test per combination). The Brands cards follow the choice and the enabled modules (`admin/lib/website-surfaces.ts`): static hides the live Web app card, web application hides the static export card, `both` shows both; Landing Pages and Forms cards need their modules enabled. Unset (existing installs) behaves as before: nothing hidden. Switching is non-destructive. |
| 7 | Section Builder | **Resolved 2026-11-06** (one note) | 105 section types, 29 with selectable design variants; add/edit/delete/reorder/duplicate via the editor (Puck built-ins); content/images, colours, padding (65 blocks), typography (`typo*` fields in some packs); preview + Mobile/Tablet/Desktop viewports; linked sections reused across pages (T7.1). **Per-device configuration now exists:** every section has *Hide on mobile (under 768px)*, *tablet (768px to 1023px)* and *desktop (1024px and wider)* on its Style tab (`frontend/src/frontend/blocks/packs/device-visibility.tsx`, applied to all blocks by `composePacks`; a section with no flag renders exactly as before). Visitors get pure CSS (verified at 390 / 900 / 1280 px and on a live resize, and in the exported static site's CSS); the editor never really hides (it shows a "Hidden on ..." badge) so flagged sections stay selectable; the pre-publish check warns when a section is hidden everywhere. *Note:* drag-reorder, duplicate and delete are Puck's built-in actions and still have no interaction test of their own. Per-breakpoint spacing/typography overrides are not part of this. |
